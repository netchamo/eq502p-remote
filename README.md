# EQ502P Remote

שליטה ב-Bettermaker EQ502P מהדפדפן או מהטלפון, בלי DAW ובלי הפלאגין.

ה-EQ502P מתחבר למחשב כהתקן USB-MIDI סטנדרטי בשם **"Bettermaker 502P"**, ולא דרוש לו דרייבר. הפלאגין הרשמי שולח לו הודעות SysEx פשוטות. הפרוטוקול פוענח מתוך הפלאגין (גרסה 3.0.0), והפרויקט הזה שולח את אותן הודעות בדיוק.

> פרויקט עצמאי שאינו קשור ל-Bettermaker. הוא לא כולל אף קובץ או קוד של היצרן, רק את מבנה ההודעות שהמכשיר מקבל. משתמשים בו על אחריותכם.

**גרסה מקוונת:** https://netchamo.github.io/eq502p-remote/ – עובדת ישירות ב-Chrome במחשב ובאנדרואיד עם חיבור USB, בלי להתקין כלום.

## שלוש דרכים להשתמש

| איפה | איך | צריך להתקין? |
|---|---|---|
| Chrome או Edge, ב-Mac או ב-Windows שה-EQ מחובר אליו | פותחים את `index.html` דרך הגשר (ראו בהמשך) או דרך כל שרת מקומי, לוחצים "התחבר ב-USB" ומאשרים SysEx | לא |
| **אנדרואיד** (טלפון או טאבלט) | מחברים את ה-EQ לטלפון בכבל USB-C OTG ופותחים את הדף ב-Chrome | לא |
| **אייפון, אייפד, וכל טלפון ברשת** | מריצים את הגשר במחשב שה-EQ מחובר אליו וסורקים את ה-QR שהוא מציג | Node.js פעם אחת |

ב-Safari (כולל כל הדפדפנים באייפון) אין Web MIDI, ולכן באייפון עובדים דרך הגשר.

## הפעלת הגשר

1. מתקינים את Node.js בגרסת LTS מ-https://nodejs.org.
2. **Mac:** לוחצים פעמיים על `start-mac.command`. בפעם הראשונה ייתכן שיהיה צורך בקליק ימני ואז Open.
   **Windows:** לוחצים פעמיים על `start-windows.bat`.
3. בהרצה הראשונה מותקן מודול ה-MIDI. אחר כך הדפדפן נפתח עם קוד QR לטלפון.
4. אפשר לבדוק בלי המכשיר: `node server.js --mock`.

הגשר מזהה את המכשיר כשמחברים או מנתקים אותו. הוא שולח לחיצת יד, ממתין שהמכשיר יחזיר את מספר היחידה שלו, ואז שולח את המצב האחרון שנשמר (`last-state.json`), כך שהסשן חוזר אחרי הפעלה מחדש. כמה טלפונים יכולים לשלוט במקביל, והכפתורים מתעדכנים אצל כולם.

## בדיקה ראשונה עם המכשיר (5 דקות)

את הפרוטוקול פענחתי מהקוד, ולא בדקתי אותו מול מכשיר. כדאי לעבור על הרשימה ולשים לב לחלון "ניטור MIDI":

1. **חיבור:** הסטטוס הופך לירוק, ושורה ירוקה (←) מגיעה מהמכשיר אחרי לחיצת היד. כך נקבע מספר היחידה.
2. **ENGAGE:** מכבים ומדליקים. אמור להישמע ההבדל בין bypass ל-EQ.
3. **LOW BOOST:** מסובבים ל-10 ושומעים בוסט בבס.
4. **מתגים:** LOW FREQ (20/30/60/100), HIGH FREQ (3–16), BANDWIDTH, ATTEN SEL.
5. **DUAL MONO:** מזיזים כפתור ב-CH 2 ובודקים שרק ערוץ 2 משתנה.

אם משהו לא מגיב, שלחו לי צילום של חלון הניטור. הכי חשוב לראות מה המכשיר שולח בחזרה (השורות הירוקות).

## הפרוטוקול

```
Handshake  host → device   F0 00 12 34 00 04 F7
Set        host → device   F0 00 12 34 <unit> <cmd> <id> <v & 7F> <(v>>7)&1> F7
                           cmd 01 = selected channel / stereo, 08 = other channel (dual mono)
Report     device → host   F0 00 12 34 <unit> <00|01> <id> <lo7> <hi7> F7
```

| ID | פרמטר | ערכים |
|---|---|---|
| 15 | ENGAGE | 64 = פעיל, 0 = bypass |
| 4 | LOW BOOST | 0–250 |
| 9 | LOW ATTEN | 0–250 |
| 5 | HIGH BOOST | 0–250 |
| 10 | HIGH ATTEN | 0–250 |
| 16 | HIGH BANDWIDTH | 0 / 85 / 172 / 255 |
| 12 | HIGH FREQ (KCS) | 64,32,16,8,4,2,1 = 3,4,5,8,10,12,16 kHz |
| 13 | מתגים | LOW CPS (8,4,2,1 = 20,30,60,100 Hz) OR ATTEN SEL (64,32,16 = 5,10,20 kHz) |
| 14 | מצב | 4 = stereo, 2 = dual mono |

הבסיס לכל ערך הוא הפונקציות `juce::MidiDevice::setValue`, `Eq502pMidiBridge::setConnectedMidiDevice` ופונקציות ההמרה (lambdas) בבינארי של הפלאגין.

## קבצים

- `index.html` – ממשק השליטה (עובד גם לבד ב-Chrome דרך Web MIDI)
- `protocol.js` – הפרוטוקול והבקר המשותף
- `server.js` – הגשר: מזהה את המכשיר, מגיש את הממשק ומעביר פקודות ב-WebSocket
- `lib/tiny-ws.js` – WebSocket מינימלי, בלי תלויות
- `test/` – בדיקות לפרוטוקול: `npm test`
